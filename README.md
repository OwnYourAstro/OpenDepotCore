# OpenDepotCore

MIT-licensed, portable clean-room core for the ASTRO 25 codeplug layer.

This repository is the reusable half of OpenDepot. It owns the codeplug
container, cryptography, model and FLASHcode data, reporting, doctor, diff, and
(as the port lands) the radio transport. It has no GUI or platform dependency in
the library itself, so the same code can back the Qt desktop app, a CLI, a
WebAssembly build, and Android. The MS-CFB and RC4 implementations are validated
byte-for-byte against Windows OLE and CryptoAPI output.

> **Status: M4 in progress.** `--read-radio` now reads by partition/tag through
> the vendor `ReadAll` path, which returns every instance of a tag, so the
> incomplete per-instance request list is gone. Reads are rejected by the safety
> guard if any validated tag is missing. The pure C++ PPP/RCMP transport and
> batched writes are the next step.
>
> **M4d validated on hardware:** the in-tree serial/PPP/RCMP transport now reads
> and writes without the vendor helper or Python. On the XTS 2500: native read
> 137 records / 137 CRC-ok in ~16-20 s, native write 137 records in ~17 s,
> native read-back identical, and the radio returns to AT mode after every
> session (even after a failure).
>
> The native read now has a baked complete request set for `H46UCF9PW6BN`, so
> `--read-radio-native <port> <out.cpg>` works standalone: 137 records,
> 137 CRC-ok, ~20 s, validated. `--write-radio-native` is the clean-room writer:
> 137 records, ~17 s, identical read-back. Passing a codeplug as an optional
> second argument still overrides the request set for other models.
>
> Write safety: `ValidateRadioCodeplug` now refuses a codeplug that is missing
> any tag present in a validated complete set for the tested model. This follows
> an incident where an incomplete 96-record radio read was written to an XTS
> 2500 and left it unprogrammed; the complete set carries 96 tags and the bad
> read was missing `0x0016`, `0x0FFD`, and `0x0FFF`.

## Codeplug model

`opendepot/core/model.h` is the CPS-style object model the GUI and CLI share.
`CodeplugModel` wraps a loaded `Codeplug` and decodes it into:

- Radio information (serial, model, FLASHcode, record count).
- Zones and channels with name, RX/TX MHz, RX/TX squelch, flags and the raw
  35-byte channel entry.
- Per-channel conventional personality (`0x0FFB`) and ASTRO data (`0x0FCD`).
- Status and Message alias lists (`0x0059`, `0x005B`).
- Named lists (`0x004C`/`0x004D`/`0x004E`/`0x004F`/`0x006C`/`0x006E`).
- Scan-list membership tables (`0x0FA1`).
- A CPS section tree mirroring Digital / Radio Configuration / Conventional /
  Scan / Zone Channel Assignment, each tagged `verified`, `inferred` or
  `unknown` and linked to the records that back it.

Beyond typed entities, every record is exposed as a `RecordNode` with its tag,
instance, section, detected structure family (`name_table`, `name`, `list_page`,
`references`, `blob`), decoded names, resolved references, strings, and raw
payload. The corpus used to derive this covers 33 codeplugs and 149 tags with
**no unmapped records**.

Typed setters (`SetZoneName`, `SetChannelName`, `SetChannelFrequency`,
`SetChannelSquelch`, `SetChannelFlags`, `SetAliasEntry`, ...) mutate the
underlying records; `Save` rewrites CRCs and the directory. Unknown bytes are
preserved, and `SetRecordPayload` is the expert escape hatch.

`opendepot-cli --model <in.cpg>` prints every decoded node as JSON, and
`--schema` prints the tag/section catalog. `--hex <in.cpg> <tag> [inst]` /
`--hexall` dump raw record payloads. `tools/analyze_schema.py` builds a
multi-codeplug catalog from `--hexall` dumps.

## Layout

```
include/opendepot/core/     public C++ API (adk.h, model.h, version.h)
include/opendepot/opendepot_c.h   stable C ABI
src/adk.cpp                 container, records, identity, report, doctor, diff
src/model/codeplug_model.cpp  CPS-style codeplug object model
src/flashcode_db.cpp        FLASHcode platforms
src/model_db.cpp src/model_db.h   generated model schemas (internal)
src/version.cpp             version surface
src/crypto/                 portable MD5, RC4, SHA-256
src/container/cfb.cpp       portable MS-CFB reader/writer
src/capi/                   C ABI implementation
src/container/ src/crypto/ src/model/ src/flashcode/ src/report/ src/doctor/
src/diff/ src/radio/        target layout for the M2/M3 split
data/                       generated binary resources
tests/                      fixtures, expected outputs, parity + unit tests
tools/cli/                  opendepot-cli harness over the public API
tools/                      data generators (migrate in M2)
docs/                       format and protocol notes
```

## Build

```sh
cmake -S . -B build -DOPENDEPOT_BUILD_TESTS=ON
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

## Fixtures

`tests/fixtures/` holds synthetic codeplugs generated by OpenDepot's own
built-in schemas with fake serials (`TEST000001`...). Expected outputs in
`tests/expected/` were captured from the `m0-baseline` legacy CLI and are the
parity target for the extraction. See `tests/fixtures/NOTICE.md` for provenance
and `tests/fixtures/MANIFEST.json` for hashes.

## Warning

This software is experimental reverse-engineered work. It can brick a radio.
